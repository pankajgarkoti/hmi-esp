# RLCD recovery and setup run contract

- **Outcome:** connected RLCD-4.2 remains on its automaton unless a real physical button or valid acoustic cue requests a different surface; user can provision Wi-Fi from Settings and see battery level on the landscape screens.
- **Workflow:** diagnose witnessed loop, implement and test focused fix, implement Wi-Fi setup and battery display, verify on connected board, publish source to existing `pankajgarkoti/hmi-esp` fork.
- **Authority:** workspace changes and flashing connected board are authorized by the user; no deletion of SD worlds/NVS. The unrelated AgentDeck daemon targeting the same USB device may be stopped to isolate the board, then checked for recurrence.
- **Evidence:** live serial log from `f4dbbbc` shows repeated `BOOT Click`, `STATUS` and `surface Clock` without physical inputs or detected sound; `lsof` showed AgentDeck PID 66513 holding `/dev/cu.usbmodem101`; its daemon sends `@AD2`/`@DP2` frames each second. Firmware currently interprets every byte as a shortcut (`t`, `b`, `s`) and AgentDeck resets unacknowledged USB links.
- **Acceptance:** idle board stays on Life through a bounded observation including the former companion's frames; real controls still operate; Wi-Fi setup is reachable via Settings, stores credentials only on-device, joins the network and synchronizes time; battery indication renders and reflects hardware readings; SD worlds and existing saved settings survive update; tests, flash and revision observation pass.
- **Decisions:** remove unframed USB shortcuts, use a physical-button-activated temporary Wi-Fi setup AP and minimal local form rather than enter passwords with two buttons. Keep first-boot compiled credentials as fallback, never display or log passwords.
- **Ask only if:** board disappears and cannot enter download mode, or an unforeseen credential/security choice materially alters setup. Stop after physical verification and publication.
- **Status:** competing companion stopped. Exact AgentDeck-style frames are rejected by unit and live USB tests, with no unsolicited surfaces. Audible cues no longer interrupt Settings. The 16 SD worlds survive reflashes.
- Wi-Fi Setup started an on-board WPA2 AP and HTTP server; an on-device HTTP POST to the actual AP interface was accepted. The previously configured 2.4 GHz SSID was unavailable during that test, so join timed out and the previous configuration was retained. Joining a reachable replacement network and persistence across reboot require a phone-path test.
- Battery output is shown on landscape home/clock; on-board ADC reports about 4.11 V and 98% during this run.
- Next: publish the verified source, flash the exact revision, inspect stable Life and AP setup. Ask user to exercise the phone form with a reachable 2.4 GHz network; do not claim connection success until observed.
